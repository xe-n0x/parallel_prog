# Лабораторная работа №2

## Тема

Параллельное умножение двух квадратных матриц на языке C++ с использованием OpenMP.

## Цель работы

Реализовать параллельную версию программы для умножения квадратных матриц и сравнить её время работы с последовательной реализацией из лабораторной работы №1.

## Задание

Необходимо написать программу на языке C/C++ для перемножения двух квадратных матриц с использованием технологии OpenMP.

**Исходные данные:** файлы, содержащие значения исходных матриц.

**Выходные данные:** файл со значениями результирующей матрицы, временем выполнения и объёмом задачи.

**Дополнительное требование:** выполнить автоматизированную проверку результата вычислений с помощью сторонней библиотеки или стороннего программного обеспечения.

## Формат входных данных

Входные матрицы хранятся в текстовых файлах `matrixA.txt` и `matrixB.txt`.

Матрицы являются квадратными и имеют размер `N × N`.

## Описание алгоритма

В лабораторной работе используется классический алгоритм умножения матриц, но вычисления распределяются между потоками OpenMP.

Пусть заданы две квадратные матрицы:

- `A` размера `N × N`;
- `B` размера `N × N`.

Результирующая матрица `C` также имеет размер `N × N`.

Каждый элемент результирующей матрицы вычисляется по формуле:

```text
C[i][j] = A[i][0] * B[0][j] + A[i][1] * B[1][j] + ... + A[i][N-1] * B[N-1][j]
```

В общем виде:

```text
C[i][j] = sum(A[i][k] * B[k][j]), где k = 0 ... N - 1
```

В последовательной версии все элементы матрицы вычислялись одним потоком. В параллельной версии часть итераций внешнего цикла распределяется между несколькими потоками:

```cpp
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        for (int k = 0; k < p; k++) {
            C[i][j] += A[i][k] * B[k][j];
        }
    }
}
```

В тестировании использовалось `16` потоков.

## Теоретическая сложность

Сам алгоритм умножения матриц не изменился: для каждой пары индексов `(i, j)` выполняется проход по индексу `k`.

Для квадратных матриц размера `N × N` количество итераций внутреннего цикла равно:

```text
N^3
```

Асимптотическая сложность алгоритма остаётся:

```text
O(N^3)
```

При этом OpenMP позволяет выполнять часть вычислений одновременно на нескольких потоках, поэтому фактическое время выполнения становится меньше, чем у последовательной версии.

## Автоматизированная проверка результата

Проверка результата выполняется с помощью Python-скрипта `eqw.py`.

Скрипт:

1. считывает исходные матрицы `matrixA.txt` и `matrixB.txt`;
2. считывает результат из `matrixC.txt`;
3. вычисляет контрольный результат с помощью функции `numpy.dot`;
4. сравнивает результат C++-программы с результатом NumPy.

Если результат совпадает, в итоговом файле фиксируется статус:

```text
Correctly: 1
```

## Сравнение с лабораторной работой №1

В лабораторной работе №1 использовалась последовательная версия программы. Во второй лабораторной работе использовалась параллельная версия на OpenMP с `16` потоками.

| Размер матриц | ЛР №1, последовательная версия | ЛР №2, OpenMP 16 потоков | Ускорение | Снижение времени |
|---:|---:|---:|---:|---:|
| `200 × 200` | `119 ms` | `39 ms` | `3.05` | `67.2%` |

## Анализ результатов

По результатам тестирования видно, что OpenMP-версия работает быстрее последовательной реализации на всех размерах матриц.

Для матриц `200 × 200` время выполнения уменьшилось со `119 ms` до `39 ms`, то есть примерно в `3.05` раза. На небольшом размере матрицы ускорение ниже, потому что часть времени уходит на создание и распределение работы между потоками.

Для матриц `400 × 400`, `800 × 800` и `1600 × 1600` ускорение находится примерно в диапазоне от `3.66` до `3.81` раза. Это показывает, что при увеличении размера задачи параллельная версия используется эффективнее, так как вычислительной работы становится больше.

На самом крупном тесте `1600 × 1600` время выполнения уменьшилось с `43.765` секунды до `11.961` секунды. Это примерно в `3.66` раза быстрее последовательной версии.

Программа считывает исходные матрицы из файлов, выполняет умножение, сохраняет результирующую матрицу и фиксирует время выполнения. Корректность результата проверяется с помощью сторонней библиотеки NumPy.

Полученные результаты показывают, что параллельное выполнение позволяет ускорить классический алгоритм умножения матриц, особенно на больших размерах входных данных.
