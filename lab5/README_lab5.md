## Задание

## Краткое описание алгоритма

В лабораторной работе используется классический алгоритм умножения матриц:

```text
C[i][j] = sum(A[i][k] * B[k][j]), где k = 0 ... N - 1
```

Последовательная сложность алгоритма остаётся кубической:

```text
O(N^3)
```

Для распараллеливания используется MPI. Основная идея состоит в том, что строки результирующей матрицы распределяются между несколькими процессами.

Общая схема работы программы:

1. Процесс с рангом `0` подготавливает исходные данные.
2. Данные распределяются между MPI-процессами.
3. Каждый процесс вычисляет свою часть строк результирующей матрицы.
4. Частичные результаты собираются обратно на процессе `0`.
5. После завершения вычислений фиксируется время выполнения.

При таком подходе каждый процесс выполняет только часть общей работы, а не умножает матрицы целиком.

---

## Использование MPI

MPI используется для запуска нескольких процессов, которые могут выполняться на разных вычислительных ядрах кластера.

В отличие от OpenMP, где несколько потоков работают в общей памяти одного процесса, в MPI каждый процесс имеет собственную память. Поэтому обмен данными между процессами должен быть организован явно.

В данной лабораторной работе MPI применяется для:

- определения номера текущего процесса;
- определения общего количества процессов;
- распределения строк матрицы между процессами;
- сбора частичных результатов после вычислений;
- синхронизации параллельного выполнения.

## Подключение и окружение

Работа выполнялась в среде Linux Ubuntu 24.04. Подключение к суперкомпьютеру выполнялось через терминал по протоколу **SSH**.

Передача исходных файлов и результатов выполнялась с помощью утилиты **SCP**. Запуск программы выполнялся в консольном режиме на вычислительных ресурсах кластера.

Примерная схема работы:

```bash
scp ./lab5_mpi.cpp user@cluster:/home/user/lab5/
ssh user@cluster
mpic++ -O2 lab5_mpi.cpp -o lab5_mpi
mpirun -np 16 ./lab5_mpi
```

Конкретное количество процессов задавалось при запуске программы.

## Анализ результатов

По результатам тестирования видно, что увеличение количества MPI-процессов в большинстве случаев уменьшает время выполнения программы.

На малых размерах матриц, например `100 × 100` и `200 × 200`, результаты не являются достаточно показательными. Время выполнения слишком маленькое, поэтому погрешность измерения и накладные расходы MPI оказывают сильное влияние на итоговые значения. В таких случаях добавление процессов может почти не давать заметного выигрыша.

На средних и больших размерах матриц эффект от распараллеливания становится значительно заметнее. Например, для матрицы `1600 × 1600` время уменьшилось с `5340 ms` на одном процессе до `480 ms` на шестнадцати процессах. Для матрицы `2000 × 2000` время уменьшилось с `10310 ms` до `931 ms`.

Это объясняется тем, что при увеличении размера матрицы объём вычислений растёт быстрее, чем накладные расходы на обмен данными между процессами. Поэтому для больших матриц MPI-распараллеливание используется эффективнее.

Также видно, что ускорение не является идеально линейным. При увеличении количества процессов появляются дополнительные затраты на распределение данных, синхронизацию и сбор результатов. Поэтому при переходе, например, от `12` к `16` процессам ускорение есть, но оно не всегда пропорционально увеличению числа процессов.

## Особенности выполнения на суперкомпьютере

Запуск на суперкомпьютере отличается от запуска на обычном персональном компьютере тем, что программа выполняется на выделенных вычислительных ресурсах. Это позволяет использовать больше процессов и получать более стабильные результаты на крупных задачах.

При этом важно учитывать, что MPI-программа зависит не только от скорости вычислений, но и от качества распределения данных между процессами. Если объём задачи мал, то время на обмен и синхронизацию может быть сопоставимо с временем самих вычислений. На больших матрицах вычислительная часть начинает преобладать, поэтому параллельная версия показывает лучший результат.

## Вывод

В ходе лабораторной работы была исследована работа параллельной программы умножения квадратных матриц с использованием MPI на суперкомпьютерном кластере.

Программа распределяет вычисления между несколькими MPI-процессами. Каждый процесс обрабатывает свою часть строк результирующей матрицы, после чего результаты собираются в итоговую матрицу.

Полученные результаты показывают, что MPI эффективно ускоряет вычисления на больших матрицах. На размере `2000 × 2000` время выполнения уменьшилось с `10310 ms` на одном процессе до `931 ms` на шестнадцати процессах. Ускорение составило примерно `11.2` раза.

На маленьких матрицах эффект от распараллеливания выражен слабее, потому что накладные расходы MPI становятся слишком заметными по сравнению с полезной вычислительной нагрузкой.

Таким образом, использование MPI на суперкомпьютере оправдано для крупных задач, где объём вычислений достаточно большой и может быть эффективно распределён между несколькими процессами.
