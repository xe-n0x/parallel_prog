# Лабораторная работа №3

## Тема

Параллельное умножение двух квадратных матриц на языке C++ с использованием MPI.

## Цель работы

Реализовать параллельную версию программы для умножения квадратных матриц с использованием технологии MPI и сравнить время её работы с последовательной реализацией из лабораторной работы №1.

## Задание

Необходимо написать программу на языке C/C++ для перемножения двух квадратных матриц с использованием технологии MPI.

**Исходные данные:** файлы, содержащие значения исходных матриц.

**Выходные данные:** файл со значениями результирующей матрицы, временем выполнения и объёмом задачи.

**Дополнительное требование:** выполнить автоматизированную проверку результата вычислений с помощью сторонней библиотеки или стороннего программного обеспечения.

## Используемые файлы проекта

| Файл | Назначение |
|---|---|
| `lab3.cpp` | Основная C++-программа: чтение матриц из файлов, параллельное умножение с использованием MPI, измерение времени выполнения и запись результата. |

## Формат входных данных

Входные матрицы хранятся в текстовых файлах `matrixA.txt` и `matrixB.txt`.

В первой строке файла указывается размер матрицы:

```text
N M
```

Далее записываются элементы матрицы. В рамках лабораторной работы используются квадратные матрицы размера `N × N`.

Пример запуска генерации матриц:

```bash
python generate_matrix.py --file matrixA.txt --N 400 --M 400 --mini 1 --maxi 10
python generate_matrix.py --file matrixB.txt --N 400 --M 400 --mini 1 --maxi 10
```

## Описание алгоритма

В лабораторной работе используется классический алгоритм умножения матриц, но вычисления распределяются между несколькими MPI-процессами.

Пусть заданы две квадратные матрицы:

- `A` размера `N × N`;
- `B` размера `N × N`.

Результирующая матрица `C` также имеет размер `N × N`.

Каждый элемент результирующей матрицы вычисляется по формуле:

```text
C[i][j] = A[i][0] * B[0][j] + A[i][1] * B[1][j] + ... + A[i][N-1] * B[N-1][j]
```

В общем виде:

```text
C[i][j] = sum(A[i][k] * B[k][j]), где k = 0 ... N - 1
```

В последовательной версии все строки результирующей матрицы вычислялись одним процессом. В MPI-версии строки матрицы распределяются между несколькими процессами.

Общая схема работы программы:

```text
1. Процесс с rank 0 считывает matrixA.txt и matrixB.txt.
2. Размер матриц передаётся всем процессам через MPI_Bcast.
3. Матрица B передаётся всем процессам, так как она нужна каждому процессу для вычислений.
4. Строки матрицы A распределяются между процессами.
5. Каждый процесс вычисляет свой блок строк результирующей матрицы C.
6. Процесс с rank 0 собирает части результата от остальных процессов.
7. Процесс с rank 0 записывает matrixC.txt и matrixAB.txt.
8. Корректность результата проверяется через eqw.py.
```

В реализации сохранена структура матриц через `vector<vector<int>>`. Поэтому передача данных между процессами выполняется построчно: каждая строка `vector<int>` хранится в памяти непрерывно и может быть передана через MPI.

Упрощённый фрагмент логики вычисления локальной части результата:

```cpp
for (int i = 0; i < local_rows; i++) {
    for (int j = 0; j < n; j++) {
        for (int k = 0; k < n; k++) {
            local_C[i][j] += local_A[i][k] * B[k][j];
        }
    }
}
```

## Используемые MPI-процедуры

В программе используются следующие основные процедуры MPI:

| Процедура | Назначение |
|---|---|
| `MPI_Init` | Инициализация MPI-среды. |
| `MPI_Comm_rank` | Получение номера текущего процесса. |
| `MPI_Comm_size` | Получение общего количества процессов. |
| `MPI_Bcast` | Передача размера матриц и матрицы `B` всем процессам. |
| `MPI_Send` | Отправка строк матрицы `A` и частей результата между процессами. |
| `MPI_Recv` | Приём строк матрицы `A` и частей результата между процессами. |
| `MPI_Barrier` | Синхронизация процессов перед замером времени и после вычислений. |
| `MPI_Wtime` | Измерение времени выполнения параллельной части программы. |
| `MPI_Finalize` | Завершение работы MPI-среды. |

## Теоретическая сложность

Сам алгоритм умножения матриц не изменился: для каждой пары индексов `(i, j)` выполняется проход по индексу `k`.

Для квадратных матриц размера `N × N` количество операций умножения и сложения пропорционально:

```text
N^3
```

Асимптотическая сложность алгоритма остаётся:

```text
O(N^3)
```

MPI не меняет сложность алгоритма, но позволяет распределить вычисления между несколькими процессами. За счёт этого фактическое время выполнения может уменьшаться. При этом появляются дополнительные накладные расходы на передачу данных между процессами.

## Автоматизированная проверка результата

Проверка результата выполняется с помощью Python-скрипта `eqw.py`.

Скрипт:

1. считывает исходные матрицы `matrixA.txt` и `matrixB.txt`;
2. считывает результат из `matrixC.txt`;
3. вычисляет контрольный результат с помощью функции `numpy.dot`;
4. сравнивает результат C++-программы с результатом NumPy.

Если результат совпадает, в итоговом файле фиксируется статус:

```text
Correctly: 1
```

```powershell

```

## Сравнение с лабораторной работой №1

В лабораторной работе №1 использовалась последовательная версия программы. В третьей лабораторной работе используется параллельная версия на MPI.

Ниже приведено сравнение последовательной версии с MPI-версией на `4` и `8` процессах.

## Анализ результатов

По результатам тестирования видно, что MPI-версия позволяет заметно ускорить выполнение программы на средних и больших размерах матриц.

Для размера `400 × 400` время работы уменьшилось с `0.749 s` в последовательной версии до `0.15 s` на `4` процессах и до `0.093 s` на `8` процессах. Ускорение относительно последовательной версии составило примерно `4.99` и `8.05` раза соответственно.

Для размера `800 × 800` время работы уменьшилось с `5.422 s` до `1.18 s` на `4` процессах и до `0.73 s` на `8` процессах. Ускорение составило примерно `4.59` и `7.43` раза.

Для размера `1600 × 1600` время работы уменьшилось с `43.765 s` до `12.89 s` на `4` процессах и до `7.12 s` на `8` процессах. Ускорение составило примерно `3.40` и `6.15` раза.

На малом размере `200 × 200` результаты нестабильнее. При запуске на `4` процессах MPI-версия оказалась медленнее последовательной, так как накладные расходы на обмен данными и запуск процессов стали существенными относительно малого объёма вычислений. При запуске на `8` процессах был получен лучший результат, однако для окончательной оценки малых размеров желательно проводить несколько запусков и усреднять время.

В целом увеличение числа процессов с `4` до `8` уменьшает время выполнения на всех тестовых размерах. Однако ускорение не является строго линейным, потому что часть времени тратится не на вычисления, а на передачу данных, синхронизацию процессов и сбор результата.

## Вывод

В ходе лабораторной работы была разработана параллельная версия программы для умножения двух квадратных матриц на языке C++ с использованием MPI.

Программа считывает исходные матрицы из файлов, распределяет вычисления между MPI-процессами, сохраняет результирующую матрицу и фиксирует время выполнения. Корректность результата проверяется с помощью сторонней библиотеки NumPy через скрипт `eqw.py`.

По сравнению с последовательной реализацией из лабораторной работы №1, MPI-версия показала заметное уменьшение времени выполнения на матрицах `400 × 400`, `800 × 800` и `1600 × 1600`. Для `8` процессов ускорение составило примерно от `6.15` до `8.05` раза на основных тестовых размерах.

Сравнение запусков на `4` и `8` процессах показало, что увеличение числа процессов уменьшает время выполнения программы. Наиболее стабильный выигрыш наблюдается на больших матрицах, где объём вычислений достаточно велик и накладные расходы MPI меньше влияют на итоговое время.
