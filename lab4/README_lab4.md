# Лабораторная работа №4

## Тема

Параллельное умножение двух квадратных матриц на языке C++ с использованием технологии CUDA.

## Цель работы

Реализовать CUDA-версию программы для умножения квадратных матриц и сравнить время выполнения с предыдущими реализациями: последовательной версией, OpenMP-версией и MPI-версией.

## Задание

Необходимо написать программу на языке C/C++ с использованием CUDA для перемножения двух квадратных матриц.

**Исходные данные:** файлы, содержащие значения исходных матриц.

**Выходные данные:** файл со значениями результирующей матрицы, временем выполнения и объёмом задачи.

**Дополнительное требование:** выполнить автоматизированную проверку результата вычислений с помощью сторонней библиотеки или стороннего программного обеспечения.

## Формат входных данных

Входные матрицы хранятся в текстовых файлах `matrixA.txt` и `matrixB.txt`.

Первая строка файла содержит размеры матрицы:

```text
N M
```

Далее идут элементы матрицы.

В данной лабораторной работе используются квадратные матрицы размера `N × N`.

## Описание алгоритма

В лабораторной работе используется классический алгоритм умножения матриц, но вычисления выполняются на графическом процессоре с помощью CUDA.

Пусть заданы две квадратные матрицы:

- `A` размера `N × N`;
- `B` размера `N × N`.

Результирующая матрица `C` также имеет размер `N × N`.

Каждый элемент результирующей матрицы вычисляется по формуле:

```text
C[i][j] = A[i][0] * B[0][j] + A[i][1] * B[1][j] + ... + A[i][N-1] * B[N-1][j]
```

В общем виде:

```text
C[i][j] = sum(A[i][k] * B[k][j]), где k = 0 ... N - 1
```

В CUDA-версии один поток GPU вычисляет один элемент результирующей матрицы `C`.

Общая схема работы программы:

```text
1. CPU считывает matrixA.txt и matrixB.txt.
2. CPU выделяет память на GPU.
3. CPU копирует матрицы A и B в видеопамять.
4. GPU запускает CUDA-kernel.
5. Каждый CUDA-поток вычисляет один элемент C[i][j].
6. CPU копирует результат C обратно из видеопамяти.
7. CPU записывает matrixC.txt.
8. Результат проверяется с помощью eqw.py.
```

Фрагмент CUDA-kernel:

```cpp
__global__ void matrix_multiply_kernel(
    const int* A,
    const int* B,
    int* C,
    int n
) {
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;

    if (row < n && col < n) {
        int sum = 0;

        for (int k = 0; k < n; ++k) {
            sum += A[row * n + k] * B[k * n + col];
        }

        C[row * n + col] = sum;
    }
}
```

## Конфигурация сетки и блоков

В CUDA потоки объединяются в блоки, а блоки образуют сетку. В данной работе были протестированы две конфигурации:

| Конфигурация блока | Потоков в одном блоке |
|---:|---:|
| `16 × 16` | `256` |
| `32 × 16` | `512` |


## Теоретическая сложность

Алгоритм умножения матриц не изменился: для каждого элемента `C[i][j]` выполняется проход по индексу `k`.

Для квадратных матриц размера `N × N` количество итераций внутреннего цикла равно:

```text
N^3
```

Асимптотическая сложность алгоритма остаётся:

```text
O(N^3)
```

CUDA не меняет математическую сложность алгоритма, но позволяет выполнять большое число вычислений параллельно на GPU.

## Анализ результатов

По результатам тестирования видно, что CUDA-версия работает значительно быстрее предыдущих CPU-реализаций на всех размерах матриц.

На размере `200 × 200` время выполнения CUDA-версии уже меньше, чем у последовательной, OpenMP и MPI-версий. Однако на малых размерах матриц значительная часть времени уходит не на сами вычисления, а на накладные расходы CUDA: выделение памяти, копирование данных между CPU и GPU и запуск kernel.

На размерах `400 × 400`, `800 × 800` и `1600 × 1600` преимущество CUDA становится особенно заметным. Это связано с тем, что количество вычислений растёт как `N^3`, а GPU способен выполнять большое число операций параллельно.

Сравнение двух конфигураций блока показывает, что увеличение числа потоков в блоке с `256` до `512` не всегда гарантирует ускорение. Для размера `200 × 200` конфигурация `16 × 16` оказалась немного быстрее. Для более крупных размеров лучше показала себя конфигурация `32 × 16`.

## Вывод

В ходе лабораторной работы была разработана CUDA-версия программы для умножения двух квадратных матриц.

Программа считывает исходные матрицы из файлов, копирует данные в память GPU, выполняет параллельное умножение с помощью CUDA-kernel, сохраняет результирующую матрицу и фиксирует время выполнения. Корректность результата проверяется с помощью сторонней библиотеки NumPy.

В CUDA-реализации один поток GPU вычисляет один элемент результирующей матрицы. Такой подход позволяет эффективно использовать большое количество параллельных потоков на видеокарте.

В ходе тестирования были сравнены две конфигурации блоков: `16 × 16` и `32 × 16`. На большинстве размеров матриц конфигурация `32 × 16` показала меньшее время выполнения, однако на маленьком размере `200 × 200` быстрее оказалась конфигурация `16 × 16`.

Полученные результаты показывают, что использование CUDA позволяет значительно ускорить классический алгоритм умножения матриц, особенно на больших размерах входных данных. При этом итоговая производительность зависит не только от размера матрицы и мощности GPU, но и от выбранной конфигурации сетки и блоков.
